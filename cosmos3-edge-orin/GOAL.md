## Completion gates

1. Identify the physical device, actual RAM, storage, firmware, and network/SSH access. Install a compatible JetPack and verify CUDA/TensorRT on that Jetson.
2. Build the smallest supported Cosmos3-Edge reasoner configuration, then produce coherent image-grounded output on the Jetson using the requested backend. A UI preview, health endpoint, text-only output, or remote GPU does not satisfy this gate.
3. Serve the browser UI on the Jetson. Verify real camera or uploaded-image input, incremental generated text, stop/restart, latest-frame scheduling, and a reachable user URL.
4. Measure a fixed workload after warmup and a 10-minute sustained streaming run, without OOM, workload swap activity, or growing memory/queue usage. Save raw results and all configuration details.
5. Finish bounded optimization, document constraints and selected tradeoff, and deliver a presentation with measured figures, sources, authorship, and clearly identified novel integration work.

## Bounded optimization

Optimize after signs of life. Use batch 1, one active request, bounded context/KV cache and output, a fixed prompt/image suite, and the same power/clock/thermal conditions. No claims of global optimality.

After 5 warmup requests, measure at least 30 requests per candidate. Report p50/p95 TTFT and complete-answer latency. The client harness reports completion tokens divided by whole-request time only when genuine completion token counts are available; label this end-to-end throughput. Report isolated decode tokens/s only if backend timing instrumentation supports that measurement. Record image resolution, visual token count where available, prompt length, output token count, precision, context ceiling, engine revision, power mode, thermals, failures, and image-answer quality.

The final search is tightened to at most **5 measured candidates**, within the original ceiling of 12. The frozen [search plan](results/optimization-search-plan.json) covers FP16, two RTN scopes, one clock-policy trial within stock 25 W, and one compact engine-profile trial. Stop when that plan is exhausted. Clock policy is the explicit independent variable in its declared trial; other comparisons retain the same power/clock conditions. Stop earlier after 3 consecutive candidates without at least a 5% improvement in p50 latency or peak memory, with no greater than 5% regression in the counterpart or p95 latency. Require equivalent image-grounding quality; reject OOM, errors, sustained swapping or unbounded backlog. Use paired workloads/repeated measurements to investigate near-threshold noise. Retain the best quality-passing Pareto configurations; select the fastest one that maintains at least 512 MiB system MemAvailable through the sustained run. If that cannot be achieved, report the hardware limit explicitly rather than substituting another model/backend.
