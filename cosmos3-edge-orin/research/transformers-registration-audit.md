# Cosmos3-Edge Transformers registration and server dependency audit

**The stock pinned Transformers 5.14.1 package cannot load Cosmos3-Edge for AWQ calibration.** An official public implementation exists in Hugging Face Transformers at immutable commit **`c587bc884db2c2e31fc2b8102314656b17aa07b1`**, whose package version is `5.18.0.dev0`. This is a verified source/package finding, not a runtime test. The initial source audit installed no packages. A subsequent isolated CPU-only tokenizer test under `.qa` installed Transformers 5.14.1 and Jinja2 3.1.6 with their lightweight dependencies; no Torch stack was downloaded, and no GPU or remote host was accessed.

## Exact released package

Downloaded only the public universal wheel `transformers-5.14.1-py3-none-any.whl` into ignored `.qa/transformers-registration/`, without installing it or fetching dependencies. Its **11,625,234 bytes** match published SHA-256 **`9db974c4079ede2d1a3ea7ca5a240df33f2cc26fc2b36ba64c5f2a4f43b6e725`**. [Official PyPI release metadata](https://pypi.org/pypi/transformers/5.14.1/json)

Scanning every Python file in that wheel found zero occurrences of `cosmos3_edge`, `Cosmos3EdgeConfig`, `Cosmos3EdgeForConditionalGeneration`, or `Cosmos3EdgeProcessor`. The wheel contains `cosmos3_omni` and `Cosmos3OmniConfig`; this is a different model family. `configuration_auto.py:407–414` raises when the root model type is not in `CONFIG_MAPPING`. Our checkpoint has root `model_type: cosmos3_edge` and no remote `auto_map`, so stock AutoModel loading cannot recover by fetching checkpoint code. The generic Edge-LLM quantizer has no alternate Cosmos3 loader. [Pinned quantizer loader](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/tensorrt_edgellm/quantization/quantize.py#L227)

Machine-readable provenance and source hashes are in [transformers-registration-audit.json](../results/transformers-registration-audit.json). The previously prepared AWQ runner deliberately pins 5.14.1 and will therefore stop at its class-recognition gate; its setup instructions must be revised before attempting calibration. No runner modification is part of this audit.

## Impact on ordinary FP16 resident serving

Normal text/image requests in `experimental.server` do **not** invoke Transformers AutoProcessor/AutoConfig. The builder reads JSON directly; the native runtime has `Cosmos3EdgeViTRunner` and handles image preprocessing/token assembly. The Python HF formatter is lazy and used only when tools/tool-call messages require it. Our UI's ordinary text-plus-image requests do not meet that condition. [JSON config reader](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/experimental/builder/core/config.py#L15), [request dispatch](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/experimental/server/runtime/engine.py#L986), [tool-template trigger](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/experimental/server/parsing/tool_chat_template.py#L29), [native Cosmos3 runner](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/cpp/multimodal/cosmos3/cosmos3EdgeViTRunner.cpp#L27)

**There is a separate first-build template dependency.** The prepared snapshot contains `tokenizer.json`, `tokenizer_config.json` with `tokenizer_class: PreTrainedTokenizerFast`, and `chat_template.jinja`; it does not contain `processed_chat_template.json`. The Cosmos3 builder family has no packaged `CHAT_TEMPLATE` module. During artifact creation, `process_chat_template` therefore tries `AutoTokenizer`. If Transformers is absent or extraction fails, upstream silently writes a generic `User:`/`Assistant:` fallback. That fallback is not evidence of correct Cosmos3 prompt formatting. [Artifact flow](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/experimental/builder/core/artifacts/runtime_artifacts.py#L221), [extraction/fallback](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/experimental/builder/core/artifacts/chat_template.py#L119)

The **smallest source-grounded FP16 correction** is to include Transformers **5.14.1** and **Jinja2 3.1.6**, which are already the backend's `server-tools` extra, and verify the generated template against the checkpoint Jinja template before treating inference as valid. This does not require the newer Cosmos3 HF model class: the released `AutoTokenizer` catches an unknown `AutoConfig`, falls back to generic `PreTrainedConfig`, and then uses tokenizer metadata (`tokenization_auto.py:729–750`, `937–948` in the downloaded wheel). The subsequent CPU-only tokenizer/template smoke test **passed**: AutoTokenizer loaded the exact local snapshot without remote code, and the helper reproduced the current UI single-user prompt exactly with thinking enabled and disabled. The image placeholder delimiters also matched. See [CPU evidence](../results/cosmos3-tokenizer-preflight.json). Do not reuse an already cached generic template: the artifact writer leaves an existing processed template in place. [Backend optional dependencies](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/pyproject.toml#L76), [existing-template behavior](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/experimental/builder/core/artifacts/chat_template.py#L290)

## Smallest proposed AWQ dependency correction

The official development commit reports **`5.18.0.dev0`**, which does **not** satisfy the pinned Edge-LLM `tools`/`export`/`server-tools` requirement `transformers==5.14.1`. Installing the development build beside the unchanged `.[tools]` extra is therefore not a clean resolved dependency set. [Development version](https://github.com/huggingface/transformers/blob/c587bc884db2c2e31fc2b8102314656b17aa07b1/src/transformers/__init__.py#L21), [exact backend pins](https://github.com/NVIDIA/TensorRT-Edge-LLM/blob/e8b29522938901f6df19ebeedd4b69bc8edbcd97/pyproject.toml#L50)

Proposed next implementation: only in the isolated auxiliary calibration environment, install the pinned backend base package plus an explicit calibration requirements file derived from its `tools` dependencies, replacing solely the Transformers pin with the official immutable commit above. Update the original runner's dependency guard to validate that commit's installed provenance. Keep the original backend source pin unchanged and avoid claiming upstream-tested compatibility. The development package declares Python ≥3.10, Torch ≥2.5, safetensors ≥0.8.0, tokenizers ≥0.23.1,<0.24.0 and huggingface-hub ≥1.31.0,<2; the pinned Torch 2.13.0 and safetensors 0.8.0 fit those declared bounds. This does not establish ModelOpt 0.45.0 API/export compatibility. [Pinned development dependency declarations](https://github.com/huggingface/transformers/blob/c587bc884db2c2e31fc2b8102314656b17aa07b1/setup.py)

Before calibration, require CPU model/processor recognition and template checks, then an actual GPU FP16 forward pass with image activations, correct parameter/tensor loading, and the existing image-calibration/projector-precision checks. Successful calibration still needs export-schema validation and a build/quality test on the Orin. No AWQ dependency override or upstream source patch was performed. The later CPU preflight justified adding `server-tools` to the Orin build instructions and an original launcher guard against generic processed templates. [Offline guard checks](../results/cosmos3-chat-guard-check.json) accepted correct templates and rejected missing-dependency fallback and stale generic cache artifacts without importing TensorRT or launching a server.
