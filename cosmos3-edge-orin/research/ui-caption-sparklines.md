## Resource sparklines

Three charts use the existing Orin sampler, independently of inference: CPU in blue, GPU in green and shared system RAM in purple. Numeric readings and thin utilization bars remain visible. The memory chart represents `MemTotal - MemAvailable` as a percentage of Linux-visible shared RAM. It does not invent a separate dedicated VRAM pool.

With captions above or below the camera, the resource panel fills the right column beneath VLM output info. CPU and GPU share a row, with memory beneath them. Side-window mode keeps the full-width resource panel; screens at 800 px or narrower stack camera, output info and resources. Switching layouts preserves the chart elements and their history.

The browser retains up to 60 seconds of actual device sample timestamps, with a 120-point safety bound. It does not fabricate a history on page load. Repeated cached samples are deduplicated. Null, invalid, failed, stale and hidden-page periods break the line rather than becoming zeros. Genuine zero readings remain valid. A timestamp rollback starts a new history. Samples expire as the window advances.

Each chart auto-scales from zero to its observed maximum, with a 1% minimum scale. Its displayed range makes this explicit. The translucent fill and line scale for the display's pixel density and resize with the page. Accessible chart descriptions include the observed range and most recent plotted value. These choices preserve the reference's compact line-and-fill appearance while keeping missing data distinct from measured inactivity.

## Latency and Average

The current headline Latency measures only the native inference call on the Orin, after image-byte decoding, request preparation and admission. It includes native vision preprocessing/encoding, text prefill and output generation. The timer ends when native inference completes; browser JPEG encoding, server JPEG decoding, queueing and response transport are excluded. It is a server monotonic wall-clock measurement, not GPU-event time.

Average is the arithmetic mean of unrounded server durations for successful timed responses in the current settings group. Missing or invalid server metrics are explicitly unavailable and never replaced with browser elapsed time. Reloading, a new engine load, capture preset changes, or edits to image budget/top-p reset the timing population. Failed/canceled requests and responses from a prior settings group are excluded. Camera Stop/pause and caption placement preserve it. Browser first-text, round-trip and frame-age diagnostics remain expandable and explicitly include transport.

This supersedes the initial capture-to-answer metric that included browser JPEG encoding. The user explicitly requested server-side scoring, then clarified that JPEG decoding must also be excluded. Historical benchmark and UI receipts retain their original boundaries. The request-log comparator fits fixed milliseconds and marginal milliseconds per actual output token; [method and experiment status](runtime-controls-server-timing.md) explain cache controls and uncertainty. The 320-token / top-p 0.95 / 256 MiB cache / static-clock functional acceptance is preserved, but its subsequent benchmark was interrupted when the user requested the restored defaults.
