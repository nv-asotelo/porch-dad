# Contribution and license ledger

Prepared 2026-09-20 UTC from the pinned public checkouts, the downloaded model card, public GitHub contributor/commit metadata, public package metadata, and this task's implementation and result files. This is the attribution source for the presentation. It covers the principal direct dependencies and bundled backend components; it is not an exhaustive operating-system or transitive-package SBOM.

At this checkpoint the flashed Orin is running the corrected FP16 backend and the original streaming browser UI. **Corrected FP16 scores 18 of 19 required visual facts; the strict screen still fails.** The initial result was 7/19. The remaining error—calling flat purple circles spheres—also appears in the exact full answer from the unmodified official model run through public Transformers. This single-case agreement supports a separately recorded reference-equivalence policy; it does not turn 18/19 into a strict pass. The [policy](../results/optimization-quality-policy.json) was frozen before INT4 device inference and requires all 18 correct facts, complete answers and no new false claims. Evidence: [corrected quality review](../results/quality-fp16-corrected-01-review.json), [official reference comparison](../results/reference-official-05-comparison.json), [initial failed review](../results/quality-fp16-01-review.json).

The fixed FP16 run contains five warmups and 30 measured requests: p50 time to first token **266.306 ms**, p50 complete-response latency **1,830.436 ms**, and peak system shared RAM unavailable **6.3823 GiB** (6,852,915,200 bytes), with no request errors, OOM or workload swapping. The [qualified benchmark](../results/benchmark-fp16-qualified.jsonl) is an audited qualification overlay referencing the unchanged [raw run](../results/raw/benchmark-fp16-reference-01.jsonl), not a second measurement run. Shared RAM unavailable and process RSS overlap; neither is a dedicated-VRAM allocation total and they must not be added. The [completed bounded search](../results/optimization-selection.json) selects this original corrected FP16 baseline after three consecutive non-improvements. It establishes no accepted latency or memory optimization win beyond that baseline and makes no claim of a global optimum.

An original CPU round-to-nearest (RTN) converter created a **2,387,544,224-byte (2.39 GB decimal) derivative weight file**, and [all 21 transferred checkpoint files passed byte-size and SHA-256 verification](../results/rtn-transfer-verification.json). It also produced a conservative MLP-only variant that retains attention and the language head in FP16. Both variants built and ran, but failed the frozen quality policy. RTN performs no calibration: GPTQ names the storage layout only, not the conversion algorithm. The [search plan](../results/optimization-search-plan.json) capped measurement at five candidates with an earlier stop after three consecutive non-improvements; four candidates were evaluated, so the planned compact-profile fifth trial was not run.

All four runs use the same workload fingerprint, five warmups and 30 measured requests. The swap counter is global telemetry and does not identify which process caused page activity. Dynamic clocks are restored, with [all 30 saved settings independently matched](../results/deployment-memory-mode/clock-restore-verification.json). The [deployment memory receipt](../results/deployment-memory-mode/receipt.json) records swap disabled after paging in 65 MiB and 1,039,749,120 bytes of MemAvailable afterward; the swap file itself is preserved. Those operational changes are separate from the measured candidate comparison. The [final service benchmark](../results/raw/benchmark-final-service-01.jsonl), after five warmups and 30 measured requests, recorded p50 time to first text **265.540 ms**, p50 complete-answer latency **1,825.899 ms**, and **6,909,468,672 bytes (6.435 GiB)** sampled peak system RAM unavailable, with zero request errors, OOM or workload swap activity. All six final-service quality answers matched corrected FP16 exactly. The [API streaming soak](../results/raw/soak-final-service-01.summary.json) **passed 600.701 seconds and 366 requests** across all six frozen images, with no errors, token truncation, OOM or swap-in/out. Minimum MemAvailable was **1,011,798,016 bytes**; median process RSS grew **159,744 bytes** within the frozen tolerance. Median system RAM unavailable grew 2,562,048 bytes, reported separately from RSS. Peak observed active requests was one and queued requests zero. This is API stability evidence, not semantic grading or a browser-camera test.

The [final service audit](../results/final-service-audit.json) verifies both systemd services enabled and active with zero restarts, backend ready, and no active swap. A post-install physical reboot was **not tested**. The [final browser upload test](../results/browser-live-ui-final.json) passed incremental rendering, Stop with preserved partial text, restart, and no JavaScript errors against the Orin; final synthetic-camera checks also passed, within their transport-only scope.

The [final all-boot kernel audit](../results/final-service-audit.json) records **nine NVMe `completion polled` timeout warnings**, the latest at uptime **10025.646445 seconds** during cold startup. This extends the earlier [cold-reload observation](../results/nvme-cold-reload-observation.json); the earlier 30-minute window without recurrence did not establish a fix. The backend reached ready and completed the measured final benchmark and soak. These warnings do not establish a new steady-inference performance problem or its cause. The root cause remains unresolved; no kernel or NVMe power-management fix is claimed.
