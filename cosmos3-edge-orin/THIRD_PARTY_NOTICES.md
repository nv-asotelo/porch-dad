## Original integration work

Original work in this workspace consists of the compact camera/upload interface and local SSE proxy, bounded latest-frame scheduling and restart handoff, whole-frame padding, browser cancellation cleanup, streaming latency instrumentation, benchmark and stopping-rule tooling, the bounded API soak harness, source/version tracking, durable service deployment scripts, a pinned-host-key SSH/NFS bridge for the macOS USB transport, CPU RTN conversion, official-reference comparison/qualification tooling, and compatibility diagnosis, integration and regression tests. No model architecture, training, novel quantization algorithm, complete CUDA kernel, or TensorRT runtime is claimed as new work. The RTN derivative retains NVIDIA's learned model and its notices.

The positional repair still uses four-tap interpolation. General reference parity is not established when either resized image axis is below 256 pixels, because the official model's antialiased downsampling requires a wider filter. Small-axis padding in the UI is deployed as a separate mitigation for the current profile; it does not remove the backend limitation or cover direct API clients. The fixed 512×512 benchmark images are unchanged. See the [documented boundary](patches/cosmos3-half-pixel-position.md).

Corrected FP16 achieves [18/19 required facts](results/quality-fp16-corrected-01-review.json), improving on the [initial 7/19](results/quality-fp16-01-review.json), but the unchanged strict screen still fails. The official PyTorch/Transformers reference gives [the exact same complete case-05 sphere answer](results/reference-official-05-comparison.json). A [separate reference-equivalence policy](results/optimization-quality-policy.json), frozen before INT4 output, permits only that known error and requires all 18 correct facts, complete responses and no new false claims.

The [qualified FP16 baseline](results/benchmark-fp16-qualified.jsonl) references the unchanged raw five-warmup/30-measurement run: p50 TTFT 266.306 ms, p50 complete-response latency 1,830.436 ms, and peak shared RAM unavailable 6.3823 GiB (6,852,915,200 bytes), with no request errors, OOM or workload swapping. This system memory counter overlaps process RSS and is not dedicated VRAM. The [completed search](results/optimization-selection.json) selects that original corrected FP16 baseline after four measured candidates and three consecutive non-improvements. The fifth planned compact-profile candidate was not run, following the early-stop rule. No accepted latency or runtime-memory optimization win over baseline is claimed.

The all-linear RTN trial measured [1,228.779 ms median completion and 4,504,547,328 bytes peak shared RAM unavailable](results/raw/benchmark-rtn-v1-rejected-01.jsonl), but failed quality at 13/19. The MLP-only trial measured [1,026.562 ms and 5,384,015,872 bytes](results/raw/benchmark-rtn-mlp-rejected-01.jsonl), but its 18/19 score trades the permitted sphere error for a new yellow-to-orange error and therefore fails equivalence; system-wide swap activity also occurred. Static-clock FP16 [preserved every baseline answer](results/quality-fp16-clocks-01-review.json) and measured [1,758.266 ms and 6,821,511,168 bytes](results/raw/benchmark-fp16-clocks-01.jsonl), but system-wide swap activity rejects the run; its 3.94% latency reduction also misses the 5% threshold. Global swap counters do not identify which process caused the page activity.

For final deployment, [dynamic clocks are restored](results/deployment-memory-mode/clock-restore-verification.json) and [swap is disabled](results/deployment-memory-mode/receipt.json), after paging in 65 MiB with 1,039,749,120 bytes MemAvailable afterward. These operational changes are separate from the candidate comparison. The [final service benchmark](results/raw/benchmark-final-service-01.jsonl), after five warmups and 30 measured requests, recorded p50 time to first text **265.540 ms**, p50 complete-answer latency **1,825.899 ms**, and **6,909,468,672 bytes (6.435 GiB)** sampled peak system RAM unavailable, with zero request errors, OOM or workload swap activity. All six final-service quality answers matched corrected FP16 exactly. The [API streaming soak](results/raw/soak-final-service-01.summary.json) **passed 600.701 seconds and 366 requests** across all six frozen images, with no errors, token truncation, OOM or swap-in/out. Minimum MemAvailable was **1,011,798,016 bytes**; median process RSS grew **159,744 bytes** within the frozen tolerance. Median system RAM unavailable grew 2,562,048 bytes, reported separately from RSS. Peak observed active requests was one and queued requests zero. This is API stability evidence, not semantic grading or a browser-camera test.

The [final service audit](results/final-service-audit.json) verifies both systemd services enabled and active with zero restarts, backend ready, and no active swap. A post-install physical reboot was **not tested**. The [final browser upload test](results/browser-live-ui-final.json) passed incremental rendering, Stop with preserved partial text, restart, and no JavaScript errors against the Orin; final synthetic-camera checks also passed, within their transport-only scope.

The [final all-boot kernel audit](results/final-service-audit.json) records **nine NVMe `completion polled` timeout warnings**, the latest at uptime **10025.646445 seconds** during cold startup. This extends the earlier [cold-reload observation](results/nvme-cold-reload-observation.json); the earlier 30-minute window without recurrence did not establish a fix. The backend reached ready and completed the measured final benchmark and soak. These warnings do not establish a new steady-inference performance problem or its cause. The root cause remains unresolved; no kernel or NVMe power-management fix is claimed.
